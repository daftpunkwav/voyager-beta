  • agentStore 881 行 SSE 状态机 → chatStore dispatch + 事件流
  • react-query 9 个 hooks → 全部经 bridge/client.ts callCapability
  • localStorage 5 个 key → 改为服务端持久(只剩主题)

4.4 关键架构差异

旧:per-call POST SSE(单 stream 单会话)

fetch('/api/v1/agent/chat/{sid}', {method: 'POST', body})
  → ReadableStream
  → parseSSEStream(reader)
  → consumeAgentSSEStream(stream, handlers)
  → 聚合到 useAgentStore.messages[]

每个会话/每次交互 = 1 个独立 HTTP 请求 + 独立流消费器。流断 = 对话结束。

新:共享 EventSource + 模式订阅

EventSource('/api/chat/stream?after_seq=...')
  → 模式订阅 [agent.message, agent.ask, agent.navigate, task.*, note.created]
  → 事件落 chatStore.dispatch
  → 同时更新 messages / cards / artifacts / question
  → 断线 lastSeq 重连 + read_missed 补齐

1 个长连接支撑所有页面所有交互;事件是持久化的(写进 events.db),可重放。

新模型的核心优势: ① 多视图(Chat 页 + FloatingChat 常驻)共用同一 store; ② 离线事件可重放(重启从 last_seq 恢复); ③ 跨页面状态保持(切到 /notes 再切回 chat,消息流不断); ④ 事件可被活动页 / 错误页 / 调试页订阅。
迁移含义:旧 agentStore.processSSEStream 14 个 case 大部分丢弃,改为 chatStore.dispatch 8 个 case。

📐 项目定位(摘自 docs/architecture.md §1)

Voyager 是一个本地优先、单用户的"agent 共生工作台":人和 agent 是同一系统里地位同等的两类行动者(actor), 共享同一份数据、同一套能力、同一条事件流。三大业务场景: 学习与了解(导入 GitHub / 书籍 / 新闻,知识图谱) · 办公(应用内编辑 Word/PPT,agent 就地改) · 编码(沙箱内运行代码,结果回灌对话)。

模块清单

10 服务 + 1 模板 + 7 平台包 + 1 gateway

领域服务(每个独立进程 · 自带队列 · REST + MCP 双协议)

notes 6 caps

Markdown 笔记服务,六件套(register + wire + rest + mcp + settings + store)。能力:create/update/delete/list/get/link。

graph 19 caps · 2 pipelines

双建图管线:programmatic(源码 + 关联度)与 AI(agent 直接 set_node/set_relationship)。引擎 C sidecar + Python 回退。

sources 20 caps · 3 子模块

聚合服务,内部 modules/{repo,books,news} 自包含,聚合层仅合并注册表。新增资源类型 = 新增子模块目录。

office 10 caps · 2 子模块

doc / slides 双子模块,聚合零逻辑。能力覆盖 Word 类与 PPT 类文档的增删改插。

llm 11 caps

提供商目录 + BYOK 密钥。set_api_key 在 framework 之外二次校验 actor.kind=USER 才放行。

code-exec 3 caps

沙箱代码执行,run_snippet / run_file 长任务(返回 JobRef)。注:未标 long_running=True(小缺口)。

browser 5 caps

Playwright 自动化能力面:navigate / click / type / read / screenshot。域名白名单。

settings 6 caps

应用外观 / 仲裁 / 触达 / 隐私等设置项聚合。secret 项由 SettingsStore 拒非 USER。

gateway 0 业务 caps

对人类唯一入口,零业务逻辑。鉴权 / 限流 / 审计 / chat 通道 / SSE / 健康聚合。

_template 脚手架

新服务的七件套模板,clone 即用,内置 long_running 校验与 entry probe stub。

平台包(横切设施 · 唯一被所有模块依赖)

contracts 纯类型

events / dto / errors / version。零依赖,TS 类型由此生成,三方认知永远一致。

capability 能力框架

一次定义 → REST + MCP 双协议生成。入口强制鉴权/限流/审计(handler 不可跳过)。

eventbus 事件流

持久化事件日志 + 游标订阅。Event.trace_id 贯穿全链,断线可按 after_seq 续传。

actor 鉴权凭证

Actor 模型(User/Agent/External)。本机会话令牌 + OAuth 2.1(MCP 标准)。

settings 设置框架

schema / 默认值 / secret 标记 / 变更事件。设置页全部按 schema 动态渲染。

secrets 密钥保管

Fernet 对称加密落盘,环境变量优先,日志脱敏。secret 设置项唯一写入口。

health 健康探测

MountSpec.probe 统一接口,HealthProbe 在 gateway 聚合。状态变化发 service.health.changed。

Agent Runtime(系统决策者 · 唯一"做事"角色)

runtime 底座

loop / scheduler / state / recovery / events / observability 十二职责。

master Lucien

主 agent,ReAct 强制。统筹 / 仲裁(排队/自动/引导)/ 摘要 / 主动触达。

subagent 派出机制

能力面裁剪 + 模式授予(ReAct/GoT/…)+ 用户自建 subagent 注册表。

policy / memory

四维权限(actor / cap / scope / 风险)+ profile / episodic / semantic / working 四类记忆。

context / skills / hooks

上下文装配 + 压缩;skill 索引常驻 + 全文按需;hook 加载 + 触发。

tools / clients

agent 自身工具(ask_user/spawn_subagent/recall_memory/fs/shell/web);MCP client 连接池 + 服务发现。

脱耦审计

services × services · platform 反向 · agent → services

✅ 横向 import 矩阵(业务代码)

services/* → services/* 的 import 完全为零(§12 依赖矩阵的服务间隔离在生产代码层严格遵守)。任何 CI 规则只需 ^from\s+services\.(\w+)\b + "非本服务目录白名单" 就能秒级扫出违规。

✅ platform 反向依赖

platform/7 个子包(actor / contracts / eventbus / capability / settings / secrets / health) → 上层 import 完全为零。 §6.7 "platform 不得 import 任何 services/agent/apps" 严格遵守。

✅ agent → services.* 实现层

agent/* 全树没有 import 任何 services.<x>.store/capabilities/worker 实现 — §6.6 "不直接写业务库表(只调 capability)" 在 import 层完全合规。 所有领域交互经 platform_capability.execute()。

✅ 聚合服务子模块互不 import

sources/{repo,books,news}、office/{doc,slides}、graph/pipelines/{code,ai} 内部均 0 互 import。所有子模块 __init__.py 空文件 — 语言层阻断了偶发耦合(任何水平 import 需显式长路径)。

接口设计

一份 Action 模型 · 一次定义双协议

91 个 Capability

notes 6 + llm 11 + graph 19 + sources 20 + office 10 + browser 5 + code-exec 3 + settings 6 + agent 11 = 91。每个含 schema + handler + 元数据(cost/scopes/reversible)。

REST + MCP 同源

platform_capability/define.py 装饰器注入 Registry,同注册表由 gen_rest.build_router 和 gen_mcp.build_server 共享,JSON Schema 复用同一生成器。

入口强制

鉴权 → 配额 → 审计 三件事在 guards.py:122-184 集中执行,handler 不可跳过。secret 类能力在 service 层再校验一次(双重门)。

统一错误码(ErrorSuffix × HTTP)

SuffixHTTP含义
UNAVAILABLE503服务不可用
QUEUE_FULL429队列满,稍后
NOT_FOUND404资源缺失
AUTH_REQUIRED401未认证
FORBIDDEN403已认证但无权限
RATE_LIMITED429限流/配额
INVALID_INPUT400入参不合法
CONFLICT409冲突
INTERNAL500内部错误
错误体统一为 { error: { code, message, service, hint, trace_id } },由 errors.py:101-102 序列化。 前端 bridge/client.ts 把后端字段映射为 ServiceError,hint 字段直接给用户"可行动建议"。

接口完整性缺口

  • 健康探测:各 service 的 /health 端点目前只回 status=UP,不查真实依赖;gateway 周期探测尚未实现(只有 probe_all() 被动触发)
  • 长任务标记:code_exec.run_snippet / run_file 实际是长任务(返回 JobRef)但未标 long_running=True,框架层不会校验
  • 能力命名:settings.get_settings 与 agent.get_settings 行为不同(前者带 module 过滤),但均可工作,不影响前端

安全设计亮点

🔒 框架层集中强制鉴权/限流/审计

platform/capability/guards.py 单一入口 execute() 不可绕过。服务/handler 看不到守卫逻辑,真正做到"权限即工具面"。

🔒 隐私例外多层防御

set_api_key 与 SettingsStore.set 在框架 LocalAuth 通过后再做一次 actor.kind is not USER 校验,单一层被绕过不影响数据。

🔒 密钥零明文痕迹

secrets/llm/store.py:1-6 顶部注释明确"本库永不存 api key",key 永不出能力出口,测试 test_llm.py:92 验证。

🔒 trace_id 端到端一致

Event.trace_id + ActorContext.trace_id + EventLog 入库 + ErrorBody.trace_id 5 层命名一致,可在活动页/错误页按 trace_id 反查。

拓展性分析

新增什么 / 哪里会卡 / 未来怎么走
